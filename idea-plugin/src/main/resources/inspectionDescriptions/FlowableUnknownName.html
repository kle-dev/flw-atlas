Reports a message, signal, task key or activity id in Java that no indexed model declares: startProcessInstanceByMessage, messageEventReceived and messageName take a message, signalEventReceived and its variants a signal, taskDefinitionKey a user-task id and activityId a flow-node id. An unknown message throws at run time; an unknown signal reaches no one and says nothing.

Example: runtimeService.signalEventReceived("DEMO-orderCancelld") is reported with the suggestion did you mean 'DEMO-orderCancelled'?

Quick fix: Replace with '…'.

Messages and signals are the names of every model in scope — a <message name>, a <signal name>, or a messageRef/signalRef that names no declaration, which the engine then takes as the name, and the signalRef of a case's signal event listener, which the same signalEventReceived reaches. A task key or activity id is judged only when the same chain names its model (processDefinitionKey("…"), caseDefinitionKey("…")), and never in a chain with or(); taskDefinitionKeyLike takes a pattern and is skipped. Variables and form outcomes are not judged.

Silent before the model index exists, when the project declares no name of that kind, when a model computes one at run time (flowable:messageExpression, flowable:signalExpression, a name holding ${…}), when a process is known only from a Design JSON file, and in test sources.
